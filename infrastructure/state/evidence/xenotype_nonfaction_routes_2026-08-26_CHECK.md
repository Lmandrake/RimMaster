## The mechanism, once, because all five routes reduce to it

`PawnGenerator.GetXenotypeForGeneratedPawn` (`Verse/PawnGenerator.cs:1698`) calls
`XenotypesAvailableFor(kind, factionDef, faction)` (`:1747`), which adds **`kind.xenotypeSet`
unconditionally, regardless of faction**. It adds `faction.def.xenotypeSet` only when
`kind.useFactionXenotypes` is true (default true, `Verse/PawnKindDef.cs:46`), and also adds
`meme.xenotypeSet` for every meme in the generating faction's primary ideo (`RimWorld/MemeDef.cs:95`).

⇒ **A PawnKindDef carrying its own `xenotypeSet` bypasses `FactionDef.xenotypeChances` entirely.**

1. **Refugees.** `QuestNode_Root_RefugeePodCrash_Ghoul.GeneratePawn_NewTemp:20` generates

   `ShamblerSwarmer`, `Metalhorror`, `Trispike` and the Ghoul/Shambler incidents. So this route is
   **closed here**, and the example above is dead. The MECHANISM stands unchanged; only the vanilla
   illustration of it does not exist in this game. ⛔ Do not cite `Ghoul` as a live route.
   ✅ `Sanguophage` is **not** in the removal set, so route 2 below is live.
   Harvest: `infrastructure/state/logs/harvest_2026-08-26/cherrypicker_removals.txt`.
2. **Sanguophage.** `PawnKindDefOf.Sanguophage` has `useFactionXenotypes: false` and its own set.
   Generated by `QuestNode_Root_SanguophageMeetingHost.RunInt:132` and
   `QuestNode_Root_SanguophageShip.RunInt:59` against a **runtime-generated hidden faction**
   (`FactionGenerator.NewGeneratedFactionWithRelations(hidden: true)`) — never one of the twelve
   placed factions, so no faction-roster audit will ever see it.
3. **Quest-reward pawns.** `QuestNode_GeneratePawn.RunInt` builds a `PawnGenerationRequest` from
   XML `kindDef`/`faction` and **never sets `ForcedXenotype`**, so resolution goes through the same
   `XenotypesAvailableFor`. ⚠️ The full ~300-`QuestScriptDef` sweep for a `kindDef` with its own
   set is **UNMEASURED** — mechanism confirmed, roster not enumerated.
4. **Wanderers.** `QuestNode_Root_WandererJoin_WalkIn.GeneratePawn_NewTemp:32` passes
   **`faction: null`**, so `kind.xenotypeSet` is the *only* pool. `PawnKindDef Villager` has no set
   of its own, so vanilla wanderer-joins are Baseliner-only **today** — ⛔ and that is a data fact,
   not a safety property. Give `Villager` a set, or route through `overridePawnGenParams`, and it
   leaks immediately.
