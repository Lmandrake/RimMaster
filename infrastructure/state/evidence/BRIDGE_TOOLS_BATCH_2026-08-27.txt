--- 2. jawa/bridge_arg_report  — BRIDGE_DROPS_UNKNOWN_PARAMS_1 ---------------

Harmony prefix on RimBridgeServer.AnnotatedExtensionCapabilityProvider.BindArguments
(private static, RVA 0x3fb28), installed from JawaBenchInit.Announce().

Covers ALL tools on the bridge, not only this companion's, because it sits in the
shared binder. REPORT-ONLY by default; 'strict' is opt-in, deliberately — refusing in
a shared binder would change behaviour for every caller at once.

csproj: 0Harmony referenced from the Harmony mod's Current\Assemblies with
Private=false, and a CheckReferences Error added so a missing 0Harmony fails loudly
instead of emitting type-not-found noise. The bundle check confirms no second copy
ships — a second HarmonyLib in-process would mean our patch is not the one that runs.

Three limits written into the tool's own result rather than left to be discovered:
  * installed=false and zero records read IDENTICALLY, so the result carries an
    explicit blindWarning. The target is a third-party private method with no
    compatibility promise; Install() asserts it resolved and logs loudly if not.
  * The module initializer is lazy (JAWABENCH_INIT_LINE_IS_LAZY_1), so the FIRST
    tool call of a session is bound before the patch exists. Its dropped args are
    invisible; every call after it is covered.
  * It sees only what reaches BindArguments — anything
    ReflectedCapabilityBinding.NormalizeInvocationArguments rewrote upstream is gone.
