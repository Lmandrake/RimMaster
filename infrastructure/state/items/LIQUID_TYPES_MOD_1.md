# LIQUID_TYPES_MOD_1 — one liquid system, many liquids

Owner, at the Rust Cathedral sitting 2026-09-06 (verbatim on the filing event).
A mod defining liquid VARIETIES as data: per-liquid **viscosity (move cost),
damage type on contact/immersion, acidity vs basicity, color, opacity,
sediment/fine-sand and oil variants** — on tile maps AND the worldmap.

## The roster he named, plus candidates

Boiling water · frigid water · normal water · liquid propane · slime · ooze ·
tar · acid · poison · mineralized · **coolant** — plus made-up extensions:
brine (the Greentide's river graves), rainbow reaction-liquor (Scarlands
pools), fuel-sap liquor (Greentide stills), blood/ichor (Webwork nests?),
cryo-ammonia (the Flats), mud grades (churnmud).

## Consumers already ruled — this is why it pays

- Rust Cathedral **coolant canals** (this sitting) — the 8 river tiles.
- Scarlands **rainbow pools** (hot, acid, deadly) + all-toxic water variants.
- Propane Lakes (liquid fuel sea, ignition rules), Tar Pits, the Slime.
- Greentide salinity gradient (fresh → brackish → brine → salt grave).
- Terminator seas / boiling shores (`the_seas.md`), nightside frigid water.

## The trick (his words): indexing into every other mod

Vanilla + mods hard-reference `WaterShallow`/`WaterDeep` etc. in terrains,
biomes, gen-steps, pathing, fishing, swimming. Approach to evaluate first:
per-liquid TerrainDefs cloned off vanilla water (so engine water logic holds)
+ a property comp/def-extension the damage/pH/viscosity systems read; patch
index built by a generator, not by hand. Check what Vanilla Expanded / Biomes!
already do for custom waters (BMT/AB toxic waters exist — learn, don't
duplicate). Worldmap layer ties `LIQUID_BIOMES_MAP_1`.

**14 new cloned suites** (shallow+deep TerrainDefs off `WaterShallowBase`/
`WaterDeepBase`, tags/affordances unioned from the frozen dump's post-patch
`WaterShallow`/`WaterDeep` leaf — same mechanism as the acid row, unchanged):
`RM_WaterBoiling*`, `RM_WaterFrigid*`, `RM_WaterBrackish*`, `RM_WaterBrine*`
(the two brine grades), `RM_WaterPoisoned*`, `RM_Propane*`, `RM_Tar*`,
`RM_Ooze*`, `RM_WaterMineral*`, `RM_Coolant*`, `RM_ReactionLiquor*`,
`RM_FuelSap*`, `RM_Ichor*`, `RM_Ammonia*`. Acid's own `RM_AcidWater.xml`
regenerated byte-identical in its `<Defs>` body (only the header comment's

confirms the table-driven mechanism didn't drift.

**Two rows built compat-patch-only, no clone** (both folded into the one
`RM_LiquidProperties_CompatIndex.xml`, alongside acid's existing entry):
- **normal water** — §6: "vanilla, no clone... pH 7 row via patch." Baseline
  `RM_LiquidProperties` (pH 7, viscosityClass water) patched onto vanilla's
  own `WaterShallow`, `WaterDeep`, `WaterOceanShallow`, `WaterOceanDeep`,
  `WaterMovingShallow`, `WaterMovingChestDeep`, and `Marsh`.
- **slime** — §6's own row says `RM_GelatinousSlime`
  (`src/RimMandrake/GelatinousSlime`) "authors its OWN suite; this mod
  supplies the property grammar it fills in." Confirmed by reading that
  mod's `Defs/TerrainDefs/SlimeTerrain.xml`: it already ships
  `RM_Slime_Liquid`, a standalone (non-water-base) ground terrain. Cloning a
  second `RM_SlimeShallow`/`RM_SlimeDeep` off vanilla water here would
  duplicate/confuse that, so this row patches `RM_LiquidProperties`
  (viscosityClass thick, pH 7) onto `RM_Slime_Liquid` directly, plus Alpha
  Biomes' `AB_LiquidSlime` (the donor §6's "native fields carry" column
  names for slime's shape) — both `PatchOperationConditional`-guarded, so
  either target's absence no-ops rather than erroring.

**One row hand-authored, not generated:** `RM_Churnmud` (§6: "native
Mud/Marsh + one RM_Churnmud"), a single standalone TerrainDef (not a
shallow/deep pair) at `Defs/TerrainDefs/RM_Churnmud.xml`, `ParentName`
`MarshBase` (vanilla's own concrete `Marsh` def carries that `Name=`),
`pathCost` 60, `waterBodyType` None, extension viscosityClass heavy/pH 7.
Didn't fit the generator's per-row shape — one def wasn't worth bending it
for.

**Suite depth: shallow+deep, uniformly, for every row.** §6's own default
("a canal or pool liquid ships shallow+deep only; ocean/moving variants
exist where a consumer does") decided it: every named ocean/river/moving
consumer in §6 (the Scald's own already-shipped `RUT_ScaldWater*`, the
Greentide salinity gradient, Twilight/Grey seas) belongs to §7 or a worldmap
biome item — out of scope here — so no row's *in-scope* consumer needs
anything beyond shallow+deep. Whoever wires a specific ocean/moving consumer
adds that depth variant then, off this same table.

**RM_LiquidProperties ships exactly 7 fields** (viscosityClass, pH,
damageOnContact, damageOnImmersion, corrodesApparel, flammable, igniteTemp —
confirmed by reading `Source/RM_LiquidProperties.cs`, untouched here per
scope). §3's fuller field list (opacity, surfaceFilm, freezesTo/
boilsAwayTo) is design-only and was NEVER built in Spike B, so no row here
references those fields — where §6 cites "film=X" or "opacity Y" for a row
(tar, ichor, reaction-liquor), that part of the row is simply not
represented in XML yet (§4c: films are a "v2 candidate, deferred").

**Values [INVENTED unless cited] — the picks and why:**
- **Boiling water** — burn/freeze/glow values are CITED, not invented:
  1/300 shallow, 2/240 deep, `canFreeze` false, glowColor (2,154,229)/r2,
  `traversedThought` HotSpring, matched verbatim from
  `RUT_ScaldWater.xml`/`REGROWTH_BOILING_LIFT_SPEC.md` R-B4a. No extension
  emitted — native fields already carry the whole "immersion hurts more
  than contact" story via the two different TerrainDefs; an extension here
  would document a neutral pH with no damage spec, the same "empty but
  valid" case §3 names directly.
- **Frigid** — pathCost 60 shallow (2x the inherited 30, "slush"); Frostbite
  1 contact / 3 immersion (Spike D's settled route: negative heatPerTick is
  inert, so cold-shock rides the corrosion code path, not a native field).
- **Brackish** — pH 7.5, viscosityClass water. **Brine** — pH 8,
  viscosityClass thick, pathCost 45 shallow ("denser than brackish"). Both
  `waterBodyType` Saltwater (native, the engine's whole salinity axis).
- **Poison** — toxicBuildupFactor 2 (within the cited 2-3 range, below
  Odyssey's own ToxicWater at 3). No extension (§6's own row: "—").
- **Propane** — `extinguishesFire` false and `waterBodyType` None (native
  overrides); pathCost 20 shallow (thin, flows easily); igniteTemp 40.
  `extinguishesFire=false` is load-bearing, not decorative: Spike C read
  `Fire.DoComplexCalcs()`'s guard directly — a Fire standing on
  `extinguishesFire:true` terrain self-destroys the same tick
  (`flammabilityMax < 0.01f`), which is exactly how the AB_PropaneLake donor
  stays inert today. Without this override, `RM_Propane*`'s own
  `LiquidIgnitionMapComponent` trigger could never do anything.
- **Tar** — pathCost 300 Standable (cited), `takeSplashes` false,
  viscosityClass heavy.
- **Ooze** — pathCost 20 shallow / 200 deep (Standable, not Impassable) —
  "between slime (RM_Slime_Liquid's pathCost 25) and mud (Mud's pathCost
  14)."
- **Mineralized** — pH 9.5 (inside the cited 9-10 "basic" range, but
  deliberately BELOW `LiquidCorrosionMapComponent`'s pH>10 threshold —
  basic-leaning, not corrosive, matching "basic" without becoming "acid's
  mirror"). `waterBodyType` Other (native, cited).
- **Coolant** — `waterBodyType` Other is CARD-ruled (MECHANICS_CARDS_
  SITTING_1 §9 CARD-2), not invented. toxicBuildupFactor 1 and `canFreeze`
  false are cited; glowColor (120,200,255) [INVENTED pale industrial
  cyan-white] for the cited "faint glow" with no color given.
- **Reaction-liquor** — pH 1 (picked acidic for "pH extreme," worse than
  plain acid's pH 2, matching "deadly"); AcidBurn 2 contact / 5 immersion;
  heatPerTick 0.02 (mild, between HotSpring's 0.01 and lava-scale).
- **Fuel-sap** — flammable true, viscosityClass thick; `extinguishesFire`
  false (same ignition prerequisite as propane, applied by the same
  reasoning though §6 doesn't cite it for this row).
- **Ichor** — viscosityClass thick, pH 7; §6's film/opacity for this row
  has no C# field to carry it (see above).
- **Cryo-ammonia** — pH 11 (real ammonia solution is basic; chosen to sit
  just past the >10 corrosion threshold on its own, matching the cited
  "mild corrosion (polar solvent)"); Frostbite 1 contact / 3 immersion for
  "cold-shock."

**Known cosmetic non-issue:** ~9 rows (brackish, brine, propane, tar, ooze,
mineralized, coolant, fuel-sap, plus both compat-only rows) will each log
one non-fatal `ConfigErrors()` advisory at live-load time ("does nothing
beyond documenting viscosity") because only pH/viscosityClass are set —
`RM_LiquidProperties.ConfigErrors()`'s `doesAnything` check doesn't count
`flammable` either (a pre-existing quirk in Spike B's C#, untouched here),
so propane/fuel-sap trip it despite being mechanically live via ignition.
Non-fatal, expected per §3 ("an empty extension is still a complete,
working liquid"), and only visible on an actual load — which is the
explicitly-deferred next item.

individually — **0 errors, 0 warnings each** (only informational "no def
