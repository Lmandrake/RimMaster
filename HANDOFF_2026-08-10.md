## 3. What changed today (all already on disk)

**`Jawa_Patches` — the project's first mod.** Four files: `About/About.xml`,
`Patches/AnimalBiomeDuplicates_Fix.xml`, `Patches/SWDesertWeather_Attach.xml`,
`Defs/WeatherDefs/SWDesertWeather.xml`. Deployed and active. Both patch files have
long header comments explaining what they do, what was verified, and when — read
those before editing either.

**Fixed: the Armadillo/Titan duplicate-biome crash.** An animal registered into the
same biome from both the biome's `<wildAnimals>` and the animal's `<wildBiomes>`
makes `BiomeDef.CommonalityOfAnimal` throw a duplicate-key `ArgumentException`. It
was silently killing three unrelated mods. **Confirmed fixed in the last load** —
Giddy-Up and Biome Compatibility Project both stopped throwing.

**Fixed: a bug we introduced.** `SWDesertWeather_Attach.xml` (authored before the
validator existed) added weather as `<li><weather>X</weather>...</li>`. But
`<baseWeatherCommonalities>` is **dictionary-keyed** — `<Clear>18</Clear>`. RimWorld
read the element name `li` as a WeatherDef name, failed, and **discarded seven entire
BiomeDefs**, including Core's Desert, ExtremeDesert and AridShrubland on a
desert-planet campaign. That single mistake produced **1,175 of the load's 1,199
cross-reference failures**, and the resulting null BiomeDefs re-killed Choose Wild
Animal Spawns (now a *null*-key crash) and killed Biome Compatibility Project.
Rewritten with correct dictionary shape, verified against Core and the modded biomes.
**Not yet confirmed in a load.**

**Fixed: the 394 "errors from long-past mods".** Not a mod problem. A single stale
settings file, `Config/Mod_3532608331_DeepStorageMod.xml` (LWM's Deep Storage, last
written 2025-12-14), held a 1,206-entry `allowedDefs` whitelist from an old mod set.
Pruned the 378 dead entries, kept the 828 live ones; all settings intact; original in
`runtime\backups\`. A full audit of all 35 `Mod_*.xml` files found no other offender.

**Removed:** RimTalk – Expand Actions and its Core (three unresolvable types; the
Social Dining feature wasn't wanted). Confirmed absent from `ModsConfig.xml`.

**Built: the `rimworld-modding` skill** at `skills\rimworld-modding\`, also packaged
as `rimworld-modding.skill`. It is designed to **keep learning** — see §6.

## 5. How we work now (earned, not preference)

**Restarts cost ~30 minutes.** Never say "restart and see". Arrive at a restart
already confident, and state in advance the exact log strings that will decide each
item in the batch.

**Verify offline first.** Defs, `About.xml`, `ModsConfig.xml` and the whole Workshop
tree are ordinary files. Confirm load order by reading `ModsConfig.xml` directly
rather than trusting the manager UI — that is how ① above was caught.

**Batch by ambiguity, not by count.** Config changes (load order, settings,
un/subscribes) carry no attribution risk and always ride along. A validated XML patch
with named log strings is safe to include. New C# assemblies and broad-patching mods
stay solo.

**Harvest the whole log.** You paid for a full load; a single yes/no is a poor return.
Update `benign_log_errors.md` every time.

**Two error phrasings, two different systems** — this cost a full investigation cycle
and is now the first section of `benign_log_errors.md`:

- `Could not **resolve** cross-reference` → def loader. A live mod-set problem.
- `Could not **load** reference to` → Scribe/deserializer. A *saved file* holds a dead
  name. This is where "errors from mods I deleted months ago" come from.

## 6. Tooling available

**`skills\rimworld-modding\`** — invoke as a skill (drop in `.claude/skills/` for
Claude Code). SKILL.md covers: read the real def first; the restart economics; the
tier ladder (bake what must be TRUE, script what must be PLACED, run live only what
must CHANGE); the four patch traps; deployment; and log triage ordered by consequence.
References cover PatchOperations/xpath, C#/Harmony/LoadFolders, and `traps.md`.

**`traps.md` is the learning log and the skill is meant to keep growing.** After any
RimWorld task, ask what surprised you and append an entry — symptom, cause, fix, and
crucially **"generalises to"**. When an entry would change default behaviour, promote
it into SKILL.md and delete it from the log. Eleven entries so far, every one paid for
with a real debug cycle.

**`skills\rimworld-modding\scripts\validate_patch.py`** — run on every patch before it
goes near the Mods folder:

```
python validate_patch.py Patches/MyPatch.xml \
  --defs "C:/Program Files (x86)/Steam/steamapps/common/RimWorld/Data" \
  --defs "C:/Program Files (x86)/Steam/steamapps/workshop/content/294100"
```

Catches `--` inside XML comments (a total-loss parse error), missing Class attributes,
`Replace` with bare text in `<value>`, unguarded modifying ops, conditional-test vs
inner-xpath mismatches, xpaths that match zero nodes (silent no-op), `Remove` xpaths
that match more nodes than intended, and — added today after it bit us — **value-shape
mismatches** against the live node's existing children.

**Pending improvement:** a `--defnames <file>` flag so it can validate against a
pre-built list of every live defName instead of walking the Defs tree. That list was
generated locally; wiring it up turns validation into a one-second set lookup.

**`Utils\animal_inventory.py`** — offline Defs scanner producing six CSVs (~112
columns): duplicates/conflicts, originating mod, stats, biome associations, shortHash
indices. It predicted the Armadillo/Titan conflict before the game ever threw it.
Re-run after any mod update. Documented in `Utils\README.md`.
