# Structure Procedural Spec — what goes in each building, and roughly where

_The owner looked at all 21 templates on `REVIEW_tile_structures_21` (2026-09-05) and
accepted none: "A LOT more work is required to make realistic rooms. These are pretty
horrible... try much harder on them all and not accept any rooms yet." This file is the
"much harder". It is a spec for FOUNDRY to build templates against, not a template._

## 0. What binds (owner, 2026-09-05 — the four rules, plus one)

| # | rule | what it means mechanically |
|---|---|---|
| **R1** | **CLEAR the whole footprint first** — rock, plants, chunks, scatter — before painting anything | a `CLEAR` pass over the footprint **plus a 1-cell buffer**, executed by the responder before terrain. Today `GenStep_RimplacePlan` only wipes what a spawned thing overlaps (`WipeMode.Vanish`); interior cells with no thing keep their cactus. **Engine delta E1, §2** |
| **R2** | **Interiors get real FLOORING**, never bare ground | every cell inside a room gets a TERRAIN entry — the room's floor tier from the palette — and a 1-cell threshold outside every exterior door gets a hard floor. `ctx:room()` already floors; the failure was templates calling `wall_rect` without `room`, and `wealth:destitute/poor` mapping FLOOR to `Gravel`. Gravel is a yard, not a floor: the poor tier becomes a **poor floor** (`StrawMatting`, `WoodPlankFloor`, `FlagstoneSandstone`), never `Gravel`, never `Sand` |
| **R3** | **Furniture breaks out of regular grids** — jitter, wall-hugging, asymmetry. Mechanical arrays are "horrible" | the placement algorithm in §3: wall-hug first, ±1 jitter along the wall, mirror ban, random-start scan for the rest. No `for zz.. for xx.. step 2` lattices for anything a person owns. **A lattice is allowed for exactly three things**: vaporators in a field, graves in a plot, mining cars on a rail — and even those get one dropped element |
| **R4** | **Every room carries SECONDARY furniture / clutter** so it reads lived-in | a per-room clutter list (§4 room recipes) and a density floor: `ceil(interior_cells / 6)` secondaries, minimum 2, and at least one PERSONAL item (chest, footlocker, end table, plant, sign, candle) per sleeping room |
| **R5** | **Depot shelf density must be walkable aisles**, not wall-to-wall (`junkers_depot`) | perimeter shelving first; at most one island row per 6 cells of width; a ≥2-wide main aisle door→back wall; every other aisle ≥1; one shelf in every 3–4 dropped and end-capped with a crate. Flood-fill proof in §3.5 |

Everything below assumes these five. A template that satisfies its roster row but fails
one of them is not done.

**Def-name discipline.** Every defName in this file was looked up in the
`defs.sqlite` capture of **2026-09-02 19:36Z** (78,831 defs; `ThingDef` coverage
`complete` at 25,032; `TerrainDef` 1,349) — none is guessed. The dump decays: run
`rimplace verify` before any template ships. Where this file says **NEW**, the def does
not exist and a mod must ship it.

## 2. Engine deltas this spec needs (FOUNDRY, before templates are reworked)

The Lua `ctx` API and the flat plan format (`RimplacePlan.cs`) cannot express R1, off-map
wiring, or a body on the ground. Six additions; the rest of this file assumes them.

| id | delta | where |
|---|---|---|
| **E1** | **`CLEAR x z w h mode`** directive. GenStep destroys, inside the rect: plants, filth, chunks and loose items, mineable natural rock (rock-wall things) — `mode=all`; or `mode=soft` (plants/filth/chunks only, leaves rock for cave-mouth templates). Cells that were rock get the matching rough-rock TerrainDef (look it up per rock type at run time — do not hardcode). Compiler emits one `CLEAR` for `footprint + 1 buffer, soft` and one for `footprint, all` FIRST, before `FOUNDATION`. `ctx:clear(x,z,w,h,mode)` for templates that want more (a cave lair clears a blob, not a rect). **Lint: `footprint-not-cleared` ERROR if the plan's first directive is not a CLEAR covering its footprint** | `plan.py compile_flat`, `RimplacePlan.cs`, `GenStep_RimplacePlan.cs`, `luaenv.py` |
| **E2** | **`RUN x z dir defName stuff`** — extend a line of `defName` from (x,z) in direction `N/S/E/W` until the MAP edge (skipping cells already holding the same def, stopping at an impassable non-conduit). Used for conduits and pipes that "go somewhere off this map". Plans cannot know the map size, so the walk is engine-side. `ctx:run(x,z,dir,role)` | same four files |
| **E3** | **`PAWN kindDef x z faction state`** — spawn a pawn (`wild`, a FactionDef name, or `player`-never) or its remains (`state=alive|dead|dessicated|skeleton`). A body is a `Corpse`, not a ThingDef; the plan cannot place one without this. Sleeping-beast lairs, dead caravans and battle sites are impossible without E3 | same, plus `PawnGenerator` in the GenStep |
| **E4** | **Prelude helpers** in `luaenv.py` (templates cannot `require`, so shared code lives in the sandbox prelude): `ctx:hug(role, room, sides, opts)` wall-hugging placement with jitter (§3.2); `ctx:clutter(room, list, n)` random-start secondary pass (§3.4); `ctx:aisle_ok(room)` flood-fill proof (§3.5); `ctx:window(x,z)` wall-slot replace (like `door`); `ctx:ruin(room, pct)` the damage pass (§8.12); `rng.jitter(r)` = `rng.int(-r,r)` | `luaenv.py`, `selftest.py` (negative controls for each) |
| **E5** | **Palette roles** added and verified: `WINDOW`, `STOOL`, `CHEST`, `CRATE`, `BARREL`, `WALL_LAMP`, `DRESSER`, `END_TABLE`, `BENCH`, `SIGN`, `PLANT`, `WATER`, `TROUGH`, `ANIMAL_BED`, `FENCE`, `GATE`, `WORKBENCH`, `FLOOR_POOR`, `FLOOR_YARD`, `FLOOR_THRESHOLD`, per tech/faction/wealth. `FLOOR` for `wealth:poor/destitute` becomes `StrawMatting` or `WoodPlankFloor` — **`Gravel` moves to `FLOOR_YARD`** (R2). The per-faction materials remain INVENTED placeholders until the owner rules (palette `_README`); this spec does not pretend otherwise |
| **E6** | **New lint rules** (`plan.py`), each with a negative control: `interior-bare-ground` ERROR (room interior cell with no TERRAIN); `regular-grid` WARN (≥3 identical defs equally spaced on a line AND ≥2 parallel such lines in one room — the lattice signature); `no-secondary` ERROR (room with a primary and zero secondary-class things — class from a role list in the palette, not a name list); `aisle-blocked` ERROR (§3.5 flood-fill cannot reach a primary) / WARN (<45% of interior reachable); `door-centred` WARN (exterior door at exact wall midpoint on a wall ≥7 long — see §3.1) | `plan.py`, `selftest.py` |

Also: `GenStep_RimplacePlan` treats an unknown directive as a **no-op** ("forward-compat"),
so an old DLL replaying a v2 plan would silently skip every `CLEAR`. **Bump the header
to `# rimplace flat plan v2` and make the GenStep `Log.Warning` once per unknown
directive** — the failure must be visible in Player.log, not on the map.

## 3. Universal placement rules — deterministic, seeded, the same for every archetype

### 3.1 Shell
1. **Order**: CLEAR (E1) → floors (every interior cell + threshold cells) → walls → doors/windows (wall-slot replace) → transmitters → connectors → furniture → secondaries → lights last → roof.
2. **Doors are off-centre.** On any exterior wall ≥7 long the door sits at `mid ± rng.int(1, floor(len/4))`, never at the midpoint (`door-centred` WARN). Never in a corner cell or adjacent to one. Interior doors likewise, and never directly opposite an exterior door on a straight line unless the archetype says "corridor".
3. **Windows** (where the archetype's tech has a window def, §1): one per 4–5 cells of exterior wall on the long side, none within 1 cell of a door, none on the sun-facing wall when `params.sun_dir` is set (tidally locked — the dayside wall is blind), none at all on `destitute`. Windows are wall-slot cells (`ctx:window`), so they count as WALL for `room-not-sealed`.
4. **Threshold**: the 1 cell (poor) or 1×3 (comfortable+) outside every exterior door gets `FLOOR_THRESHOLD` (`FlagstoneSandstone` / `PavedTile` / `Concrete` by tech). A porch = threshold + 2 `Column` + roof cells over it (roof stays within 6 of a wall).
5. **Yard**: the footprint outside the shells is `FLOOR_YARD` only where feet go — a 1-wide `PackedDirt`/`Gravel` path from the gate to every exterior door, jittered ±1 every 3 cells so it is not a ruler line; the rest stays cleared natural ground.

### 3.2 Primary furniture — `ctx:hug`
For each primary piece the room recipe names a **side preference** (list of walls, weighted) and a **mode**:
- `hug`: the piece's back cell is adjacent to the chosen wall. Position along the wall = `rng.int(1, len - size)` re-rolled while the cell is a door, adjacent to a door, or would block a window (windows may be abutted by ≤1-high things: beds yes, shelves no). Then **jitter ±1 along the wall** (`rng.jitter(1)`), clamped.
- `corner`: same, but the along-wall position is 0 or `len-size` (nearest the corner), then jitter ±1 *away* from the corner only.
- `free`: nominal cell = room centre offset toward a chosen wall by `rng.int(1,2)`, jitter ±1 both axes.
- **Mirror ban**: when two identical primaries land in one room (two beds, two shelves), they must differ in wall OR rotation OR along-wall offset by ≥1. A `barracks` recipe explicitly overrides this (soldiers' beds ARE regular — one bed is still dropped or turned).
- **Rotation** follows the wall (bed head to wall; table long axis parallel to the nearest wall); free pieces roll rotation.

### 3.3 Never a lattice
Row-major nested loops over a room are banned for anything a person owns. Where a set genuinely repeats (vaporator field, grave plot, mining rail, kennel row, barracks) the recipe says so and the set gets: one element dropped (`rng.chance(0.7)` per slot for ≥4 slots, guaranteeing ≥1 gap), and a ±1 jitter on every second element unless the thing is on a rail.

### 3.4 Secondaries — `ctx:clutter`
`n = clamp(ceil(interior_cells / 6), 2, 8)` pieces from the room's clutter list (§4), weighted, each placed by a **random-start scan**: pick a random interior cell, spiral outward until `can_place`, prefer cells adjacent to a wall or to a primary (70%: "things live against things"). Rules: ≤55% of interior cells occupied after the pass; never block a door cell or the cell in front of it; a light source must remain within 5 cells of every primary; ≥1 PERSONAL item per sleeping room (chest/footlocker/end table/plant/candle/sign/instrument/skull-trophy). Exterior yards get their own clutter list (crates by the door, a barrel under the eave, a chunk someone meant to move, a `Filth_Trash` or two).

### 3.5 Walkability — `ctx:aisle_ok`
Flood-fill from every door cell over passable interior cells (things with `passability != Impassable`; beds, tables, shelves, crates are impassable; stools/chairs/lamps are not). Every primary must have ≥1 passable neighbour in the fill; the fill must cover ≥45% of interior cells; in storerooms the fill from the exterior door must reach the back wall along a path ≥2 wide (R5). Fail → remove the last secondary and retry (max 6), then `ctx:refuse("aisle", ...)` — a refusal is a result.

### 3.6 Power and pipes (rimworld-layout-layers rules, restated once)
- Transmitters (`Battery`, generators, `PowerConduit`) are placed before connectors; a conduit **bus** runs OUTSIDE along one wall, cardinal-adjacent, and connectors (lamps, coolers, stoves) sit within `ConnectMaxDist` 6 of it — the `nursery.lua`/`hunting_lodge.lua` proven shape.
- Generators live in a **power apron** outside the shell (never in a bedroom), on `Concrete`/`Gravel`, with `Filth_MachineBits` around them; batteries under a roof (a 3×2 lean-to: 2 walls + roof + 1 `Column`).
- **Wires off-map**: where the archetype says so, a `RUN` (E2) of `PowerConduit` or `VHGE_HelixienPipe`/`OilPipeline` leaves the footprint on the side nearest the map edge (`params.edge_dir`) and walks to the edge. The player finds infrastructure that serves something else — and a free line to tap.
- Nightside (`params.latitude == "night"`): no `SolarGenerator`; `WoodFiredGenerator`/`ChemfuelPoweredGenerator`/gas; a `Heater` or `Brazier`/`Campfire` in every occupied room. Dayside (`"day"`): solar first; a `PassiveCooler` in every sleeping room; porch on the sun side. Terminator: default.

### 3.7 Variation axes every template reads

### 8.12 Battle site / mashed settlement — the ruin pass
**NEW** `battle_site.lua`, and **it is a TRANSFORM, not a layout**: it takes any other archetype's plan (default: 8.1 compound or 8.6 garrison) and damages it. Catalogue C4 (droid battlefield), E3 (garrison). Implemented as `ctx:ruin(room|plan, pct)` (E4) so every archetype gains a `state=ruined`.

Canvas = the host's. The pass, in order: (1) **breach**: pick 1–2 exterior walls; remove a contiguous 2–4 cell run (`Filth_RubbleBuilding` + `ChunkSandstone`/`SlagRubble` in and just outside the gap); (2) **attrition**: remove `pct` (20–40%) of remaining wall cells in runs of 1–3, never leaving isolated 1-cell wall stubs unless `pct>35`; (3) **roof**: remove roof over every cell within 2 of a removed wall, then `RubblePile`/`VFEPD_RubblePile` ×1 per 8 removed roof cells inside; (4) **floor**: 30% of interior TERRAIN → `BurnedCarpet`/`BurnedStrawMatting`/`BrokenAsphalt`/`AncientConcrete` by original type, `Filth_Ash` ×N, `Filth_BlastMark` at each breach and 1–2 inside; (5) **furniture**: each thing rolls — 40% stays, 25% → its ruin cousin (`Bed`→`AncientBed`, `Shelf`→`AncientShelf`, `Turret`→`VFEPD_AncientBrokenTurret`, `StandingLamp`→`AncientLamp`, crate→`AncientCrate`), 20% → `Filth_RubbleBuilding`+`ChunkSlagSteel`, 15% deleted; things that stayed get ±1 jitter (knocked); (6) **the fight**: `Sandbags`→`SandbagRubble` on 50%, `Barricade` ×2–4 improvised at the breach inside, `Filth_Blood` ×4–8 clumped at the breach and in one room, `ChunkMechanoidSlag` ×2–5 if `params.attacker=="mech"|"droid"`, `AB_Mech_RuinedTurret_Single` ×1 on droid reads, spent weapon items ×0–2 (verify names per attacker faction), `Filth_MoldyUniform` ×2; (7) **after**: `Grave` ×0–3 dug by whoever came back (lattice-allowed, uneven), `Skullspike` ×1–2 if `attacker=="hutt"|"tusken"`, `VFEPD_FilthBones`; E3 `skeleton` ×2–6 distributed 70% at the breach/inside, 30% outside the wall (they ran); (8) **time**: `Filth_Sand` drifts inside every breach 2–3 deep, `SoftSand` TERRAIN replaces the yard path. Lights: all out. Power: conduits cut in 2–3 places; the generator stays (loot), the battery is `ChunkSlagSteel`.
**NEW**: none. E3 and E4 are the whole delta.

## 10. Gaps — archetypes where the stack has no fodder for a stated element

- **Windows on anything pre-industrial** — §9 `RUT_WindowAdobe`.
- **Bodies, sleeping beasts, penned stock, defenders** — no ThingDef can be a pawn or a corpse; E3 or nothing. 8.10, 8.11, 8.12, 8.13 and A6/D3 all depend on it.
- **Carpets/rugs** as a personal-item secondary: no carpet TerrainDef name was verified in this pass (Core's carpets did not answer to `CarpetTan`) — look them up before adding a RUG role.
- **A rail** for mining cars: no rail terrain/thing — `PackedDirt` line.
- **A starship hull prop** at freighter scale: none — walls+`Substructure`+torn roof.
- **Torment Master / Breeding Ritual / Caravan Adventures tents** — active mods with relevant props whose defNames were NOT read this pass; read their Defs before citing.
- **`AncientIndustrialShelf` is inert** (`isInert`, `claimable=false`) — dressing only, never "intact stores" (imperial_waystation lesson).

## 11. How a template proves it met this spec (before any owner review)

`rimplace lint` clean including the six new rules; `rimplace verify` all defNames found against a dump whose fingerprint matches the live list; a render sheet per batch (`review-sheets`) showing THREE seeds of the same template side by side — if the three houses look like the same house, R3 failed; a live save on one map, grid key in the item (owner's standing rule), **built with the CLEAR pass on**, and `jawa/list_things` per slot, because `thingsSpawned` is a net count and lies.
