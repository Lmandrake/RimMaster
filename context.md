## The Core Concept
- RimWorld **Odyssey gravship** campaign that feels like a true mobile expedition, not a colony that owns a spaceship.
- Fantasy references: Firefly, Battlestar Galactica, Oregon Trail in space, scientific expedition across an unexplored world.
- **Central loop:** Land → choose objectives → establish temporary camp → explore → gather resources → improve ship → enemy pressure rises → abandon site → launch → repeat.

## Core Campaign Rules (from design notes)
- Start with vanilla Gravship scenario; begin with a barely functional ship.
- Enable Pursuing Mechanoids (or equivalent constant pursuit).
- Never establish a permanent planetary base; temporary camps only, disposable.
- Entire permanent colony lives aboard the ship. Crew stays small (~4–8 pawns).
- Every crew member has a meaningful ship role.
- Fuel is a strategic resource; always keep emergency launch fuel.
- Stay on a map only briefly (~10–15 days max unless story demands).
- Ship expands only after major milestones.
- Avoid giant static killboxes. Storage remains limited.
- Accept losses during emergency launches.
- Campaign ends with a major destination/final objective, not endless wandering.

## Philosophy
- Movement should solve problems. If staying forever is optimal, the gravship is irrelevant.
- Every mechanic reinforces: mobility, scarcity, exploration, hard logistical choices, deciding what to leave behind.

## Exploration Experience Goals
- Planet has recognizable destinations visible from orbit.
- Player routinely weighs: investigate ruined city? detour to fungal forest? is the psychic landmark worth the fuel? can we salvage before mechanoids arrive?
- Info level: know WHY a destination is interesting, but NOT the exact rewards.

## QoL / Storage Mod Recommendations (2026-07-31 discussion)
**Governing principle:** Adopt mods that change the *interface* freely (UI, search, smart hauling); gate mods that change the *limits* (capacity, automation).
**Key storage insight:** On a gravship the binding constraint should be the ship's FIXED FLOOR AREA (storage tile count), NOT per-tile density. Cap the number of storage tiles aboard → denser shelves just make the limited hold tidy/searchable without enabling hoarding.

- **Storage:** LWM's Deep Storage (config DOWN to ~3–4 stacks/cell, small units only); RimFridge (cap count); Adaptive Storage Framework + model pack (cosmetic, ~2024, compat uncertain). **BAN** pocket-dimension / Deep Storage Unit / quantum / networked-infinite storage ("the vortex") — deletes the leave-behind decision.
- **Searchability/UI (free to adopt):** Dubs Mint Menus (biggest search win), RimHUD, Numbers (crew-at-a-glance), Interaction Bubbles / Camera+ / Replace Stuff / Quality Builder.
- **Hauling/teardown (thematically perfect):** Pick Up And Haul + Common Sense; Allow Tool ("Haul Urgently" = the abandon-camp moment). Near-essential for a 4–8 pawn crew.
- **Landing decisions:** Map Preview (see tile before committing).
- **Tradeoff flagged:** PUAH + Allow Tool are so efficient they can undercut "accept losses on emergency launch." Counter-lever = tighten mechanoid pursuit TIMER (run out of time), not nerf hauling.

## Explorable Content / Questlines (2026-07-31 discussion)
**The core gap:** Vanilla RimWorld is a TERRAIN generator, not a PLACE generator — it scatters loose loot but has almost no authored interior space you enter and read like a level. Fatal for an expedition campaign where the whole point is land → explore → extract → leave. Content splits into 3 types:

- **Type 1 — Explorable structures ("sci-fi dungeons"):** buildings with interiors, hazards, locked sections, loot gated behind exploration. Anchor candidates: M-13 modular / ancient-complex family; vanilla Ancient Complex underground structure; Ancient Urban Ruins (surface version). **Restriction:** must NOT be strippable from outside — require sealed/interior-opened doors, interior-triggered threats, or darkness/hazard so ENTERING is the meaningful act. Anomaly mechanics fit this well.
- **Type 2 — Expanded questlines (authored objectives):** Vanilla Quests Expanded (+ Cryptoforge variant); **Go Explore! promoted to MUST-HAVE** — lost cities/signals/expedition objectives are inherently about traveling. **Restriction:** risk is a checklist, not an expedition; keep only ~2 objectives live at once — fuel constraint enforces this naturally.
- **Type 3 — Reactive biome/faction texture:** Alpha Biomes (alien/sci-fi tone) = the "pick one flavor" slot; faction/event mods make each landing feel different.

**Honest gap:** No true roguelike-scale procedural dungeon generator exists for RimWorld. Modded structures are semi-authored templates (lightly randomized) → repetition over a long game. Mitigate by STACKING several structure mods for a deep template pool, not expecting one to stay fresh.

### Anti-exponential progression philosophy (governing rule)
- **THE gravship + its industrial system are the campaign's ONLY scalable progression trees.** All other advancement systems interact multiplicatively; if several mature together the ship stops being the center. Others may exist only as: fixed backgrounds, cultural constraints, singular quest exceptions, story assets, new vulnerabilities, or mutually-exclusive choices — never repeatable optimization economies.
- **7-question test** for any new system now recorded in `forbidden_mods.md`.
- **Excluded player progression (all now in forbidden_mods.md):** psycasting (no VPE, psylinks, psytrainers, anima); genetics lab (xenotypes welcome but FIXED per pawn/pop — no gene extractors/assemblers/banks/xenogerms/breeding); fluid ideology (use FIXED **Shipborn**-centered "Articles of Passage"; no production/combat specialist roles; rituals = cohesion not material; ≤1 relic); royal permits as a route; mechanitor progression (poss. future exception: 1 inherited non-scaling utility mech); broad transhumanism/biosculpting; Project RimFactory; randomized-research/research-overhauls; Custom Quest Framework as a core dep.

## Do we still need the custom mod? (2026-08-02 — MAJOR REFRAME)
- User asked whether a custom mod is still needed; wants to avoid it as much as possible. Sharpened premise: goal is avoiding the HEAVY kind (C#, authored QuestScriptDefs, bespoke ThingDefs) — a 3-line XML PatchOperation is basically config in a folder, not "a mod" in the maintenance-burden sense.

  1. Gate factory/gravtech research → Configurable Techprints, settings only. NO custom.
  2. Keep techprints out of trader stock → Configurable Techprints, same panel. NO custom.
  3. Cap hull expansion → **VANILLA already does this** (gravcores quest-only, 6-extender cap). NO custom. → **Expansion Authorization = DROP.**
  4. Close gravlite double-route → one PatchOperation prereq on the Alloy Forge recipe, OR accept the leak. Micro-patch, not a mod.
  5. Gate/cap biofuel refinery → micro-patch or config tweak, OR accepted reframe.
  6. Inherited operate-only start line → in-game scenario editor + at most a light patch.
  7. Deterministic AUTHORED milestone quest chain (fixed rewards, named beats) → **the ONLY job that genuinely needs a heavy custom mod.** Nothing off-the-shelf gives narrative quests with guaranteed pacing.
- **Tentative conclusion:** custom mod NOT needed as specced. 6 of 7 jobs collapse into vanilla / a settings panel / trivial patches. Custom mod earns its place ONLY if deterministic story-authored quest pacing is judged worth the build.
- **The cost of going config-only:** techprints become acquirable via EXISTING/emergent quests, not authored ones. Thematically fine ("recovered a data core from a derelict"), but pacing is at the mercy of quest RNG — could stall or arrive too early. That is the real and only tradeoff.

## ASIMOV / DROID DEPOT EVALUATION — DECISIVE (2026-08-02)
