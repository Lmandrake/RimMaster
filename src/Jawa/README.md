# src/ — everything we author ourselves

Source for the RimWorld mods written for this campaign. The name is historical:
this began as one compat-patch mod, and most of what is here still is patching.
But it is **eight mods, not one, and not all of them are patches** —
`WreckedMachines/` is original art and defs that touch nothing else, and
`MissingArtFixes/` + `DesertVehicleReskin/` are pure texture overrides. Read the
contents table below before assuming what a folder is.

Load the **patch** mods last in the mod order (RimSort) so they see the final
state of every def they touch. That does not apply to content mods like
`WreckedMachines/`, which declares its own `loadAfter` in `About.xml`.

⚠️ **The folders here are sources, not deployed mods.** The game reads
`C:\Program Files (x86)\Steam\steamapps\common\RimWorld\Mods\<ModName>`. Run
`python3 src/RimMandrake/Utils/deploy_custom_mods.py` (plan-only) then `--apply`. Prefer
`--apply --mod <Name>`: a bare `--apply` pushes every mod in this folder,
including another agent's half-finished work.

## Standing preference: avoid patches when possible

Patches are a debugging tax — a mistyped xpath fails **silently**, load order
can move the target out from under you, and VEF/VFE updates rename defs between
versions. So the rule for this folder is:

1. **Prefer an existing maintained mod** that does the same thing. Only author a
   patch when no clean mod exists (or the mod is stale on the current game
   version).
2. **Wrap every patch in `PatchOperationConditional`** whose test also checks the
   target isn't already in the desired state. That turns "target moved / already
   handled" from a red error into a silent no-op.
3. **Never guess a defName or field.** Every target here was read from the
   actual mod source before writing the patch.
4. **Test in a dev-mode throwaway world** and read `Player.log` before trusting
   a patch in the campaign save.

## 🔴 One art fix, one mod, one donor — owner's ruling, 2026-08-13

> **"Each mod that we fix art in should get its own fix patch, so we could in
> theory upload it for others to use."**

**An art-fix mod targets exactly ONE upstream mod.** Not one per defect, and not
one bucket for all of them. The test is *could a stranger who owns only the donor
mod subscribe to this and have it work?* — because that is the intended end
state, and it is what forces each fix mod to be self-contained.

What the ruling requires of every art-fix mod here:

| | |
|---|---|
| **scope** | one donor mod, named in `loadAfter` and `modDependencies` |
| **`packageId`** | its own, never shared with a sibling fix mod |
| **`About.xml` description** | documents **every** file it ships, and why the donor's original is wrong — this is the Workshop description, not a note to ourselves |
| **contents** | textures (and patches) for that one donor and nothing else |

⚠️ **`MissingArtFixes/` predates this ruling and violates it.** It holds 7
textures spanning several donors — Outer Rim Galactic Diversity, Outer Rim Droid
Depot, and at least one research-kit and one apparel mod — and its description
documents only 2 of the 7.

✅ **Split done 2026-08-13** into `CereanManeFix/`, `MSEDroidFix/`, `ToolBeltFix/`
and `ResearchKitEastFix/`, all seven files now described. **`MissingArtFixes/`
itself was deliberately left intact** — it is LIVE in `ModsConfig.xml`, so
retiring it is a live change the owner sequences. Do not copy it as a pattern,
and do not add to it.

⚠️ **`loadAfter` is not boilerplate — check how the donor ships its art.** A loose
PNG beats an AssetBundle asset at the same path *regardless of load order*, so an
AssetBundle donor needs no ordering. But between two **loose** files RimWorld
resolves by load order, so a loose-art donor **must** be named in `loadAfter` or
the donor's own file wins and the fix is invisible. `MissingArtFixes` is the first
case; `DesertVehicleReskin` is the second, and the two are easy to conflate.

## Deployment — READ THIS BEFORE TESTING ANYTHING

**This folder is not what the game reads.** RimWorld loads its own copy from
`C:\Program Files (x86)\Steam\steamapps\common\RimWorld\Mods\<ModName>` and nothing
syncs the two, so editing only this folder means the change silently never reaches
the game.

**The whole procedure — plan-first `deploy_custom_mods.py`, reading the plan before
`--apply`, `-` lines and `--pull`, `DEPLOY_HOLD.txt`, validation, and the restart
that follows — is `skills/rimworld-deploy/SKILL.md`. Read it before you test
anything.**

The same shared-state rule applies to git: **commit explicit paths only.** A
`git add -A` here will sweep whatever another seat has half-written under
`src/` — including generated output mid-rebuild — into your commit.
See `CLAUDE.md`.
